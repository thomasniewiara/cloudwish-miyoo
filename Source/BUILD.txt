CLOUDWISH MIYOO 0.4 — BUILD AND TEST

Files
  game.h: shared model and declarations
  model.c: mission data, input, four spell activities, shop/home, CW3 saves
  render.c: native software graphics and pitch-aware 180-degree presentation
  audio.c: original synthesized melody and chimes, SDL audio locking
  main.c: runtime and old-save backup
  tests.c: progression, persistence, menu, display and audio regressions
  build.sh: ARM binary build
  test-host.sh: host SDL build and regression run

ARM BUILD (Linux x86_64)
Download the toolchain archive from:
https://github.com/shauninman/miyoomini-toolchain-buildroot/releases/download/v0.0.3/miyoomini-toolchain.tar.xz
Extract: tar --no-same-owner -xf miyoomini-toolchain.tar.xz -C /opt
Run: sh Source/build.sh
MIYOO_TOOLCHAIN can override /opt/miyoomini-toolchain.
The output replaces Roms/PORTS/Games/Cloudwish/cloudwish.
GCC 8.3.0; 32-bit ARM EABI5; SDL 1.2, libm and libc dynamically linked.
-Wall -Wextra -Werror is enabled. The build defines MIYOO_ROTATE_180.
No runtime shared libraries are bundled.

HOST TEST
Install SDL 1.2 development files, then:
  sh Source/test-host.sh
SDL_CONFIG can select another sdl-config binary. CC selects the compiler.
For screenshots, first create an absolute directory and pass it as an
argument to the script. The test runs with SDL dummy video/audio drivers,
isolates saves in a temporary directory and checks actual presented pixels.
It tests the same rotated presentation code used in the Miyoo binary.

To build a playable desktop program:
  cd Source
  cc -std=gnu99 -O2 main.c model.c render.c audio.c adventure.c $(sdl-config --cflags --libs) -lm -o /tmp/cloudwish-host
Run it with the working directory Roms/PORTS/Games/Cloudwish.
Desktop controls: arrows, Space=A, left Ctrl=B, left Alt=Y, left Shift=X,
right Ctrl=SELECT, E/T=L1/R1, Tab/Backspace=L2/R2, Enter=START.
Do not define MIYOO_ROTATE_180 for a normal desktop display.
Screenshot CLI: --screenshot /tmp/frame.bmp [island 0-5] [shop|map|decor|spell 0-3]

SAVES
CW3 records location, creature, position, stars, look ownership/equipment,
furniture ownership, sound setting, five mission counters and six room slots.
CW1/CW2 are imported without replaying earned rewards. Files are validated
before use; writes use temp + fflush + fsync + rename. Purchases, travel and
rewards roll back in-memory state on failed writes. Corrupt existing saves
cause an exit with a log message rather than being overwritten.
main.c attempts a one-time pre-0.4-backup.txt before replacing legacy saves.
No gameplay saves are included in the distribution.

GRAPHICS AND AUDIO
Keep the user-verified 640x480 32-bit SDL_HWSURFACE and 180-degree rotation.
Drawing and rotated presentation use separate 32-bit buffers and their own
row pitches. Each frame is blitted to the video surface before SDL_Flip.
The four creature images are the existing Cloudwish project artwork.
Other art, decorations and reactions are drawn procedurally at runtime.
The bitmap font derives from DejaVu Sans; FONT-LICENSE.txt is included.
prepare_assets.py is only needed to regenerate the original BMP sprite/font
assets from the original PNGs; assets are already included for normal builds.
Music and effects are synthesized in audio.c, with no downloaded recordings.
Onion's own stop_audioserver.sh handles native port audio setup. The run.sh
check supports older imported shortcuts as well as new Ports imports.
Sound failure is nonfatal. Hardware audio remains to be verified.

VERSION 0.4
adventure.c implements companion actions, activities and secret rewards.
adventure-render.inc extends the existing renderer without changing its
verified presentation code. CW4 appends eight validated fields to CW3.
The new regression section covers completions, repeat rewards, all five
secret gates, home actions, legacy migration, rollback and rendered screens.

Offline hints are PCM mono 22050 Hz WAV files. They were synthesized locally
with Flite's cmu_us_slt voice. No voice service, network or user recordings
are used at runtime. generate-hints.py reproduces them with local Flite and
Python audioop (Python <=3.12). Voice and music have separate saved toggles.
